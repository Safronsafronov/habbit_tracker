# Трекер привычек v3 — полоса-хитмап на 365 дней + дата начала

Дата: 2026-09-11
Статус: утверждено, готово к планированию реализации
Дополняет [2026-09-02-habit-tracker-v2-calendar.md](2026-09-02-habit-tracker-v2-calendar.md) —
переходы (карточка → месяц → год), настройки, тема, модель данных не меняются.

## 1. Обзор

Две доработки поверх v2:
1. Визуал карточки привычки на главном экране меняется с 3 мини-месяцев на
   горизонтально скроллящуюся полосу-хитмап на последние 365 дней (в стиле
   GitHub contribution graph), плюс круглая кнопка отметки сегодняшнего дня
   прямо на карточке.
2. В шите добавления/редактирования привычки появляется поле «Дата начала» —
   реальный `<input type="date">`, редактируемое, но чисто информационное
   (не ограничивает полосу/отметки).

Неизменно: переходы карточка → экран месяца → экран года, контекстное меню,
шит (свайп-закрытие, грабер), настройки/тема, структура `localStorage`,
PWA/офлайн/service worker (кроме бампа `CACHE`).

### Вне области
- Реальные напоминания/уведомления.
- Ограничение отметок датой начала.
- Изменение экранов месяца/года.
- Любые метрики/агрегаты.

## 2. Главный экран — карточка привычки

### 2.1 Было / стало
- Было: заголовок (эмодзи + название) → 3 мини-месяца (пред/тек/след).
- Стало: заголовок (эмодзи + название + круглая кнопка отметки сегодня) →
  полоса-хитмап на 365 дней с горизонтальным скроллом.

### 2.2 Круглая кнопка отметки (`.check-btn`)
- Справа в `.card-head`, `data-action="toggle-today" data-id="<habitId>"`.
- Не отмечено: контур акцентным цветом привычки (`--habit-accent`), прозрачный
  фон, без символа (или приглушённая заливка).
- Отмечено (`entries[today] === true`): заливка `--habit-accent`, белая
  галочка (✓).
- Клик:
  - `e.stopPropagation()` — не должен triggerить `open-habit` карточки.
  - `toggleEntry(state, id, today)`, `persist()`.
  - Точечное обновление DOM: класс/состояние кнопки + последняя ячейка полосы
    этой карточки (без полного `render()`), аналогично `toggle-day` в экране
    месяца.

### 2.3 Полоса-хитмап (`.heat-scroll` / `.heat-grid`)
- Контейнер `.heat-scroll`: `overflow-x:auto; -webkit-overflow-scrolling:touch;
  overscroll-behavior:contain`. Это единственное место в приложении с
  горизонтальным скроллом (остальной v2-запрет на horizontal-scroll не
  затрагивается).
- Сетка `.heat-grid`: `display:grid; grid-auto-flow:column;
  grid-template-rows:repeat(7, ...)` — 7 строк (дни недели, Пн–Вс сверху вниз),
  колонки — недели. Последняя (самая правая) колонка — неделя с сегодняшним
  днём; сегодня — соответствующая строка в этой колонке.
- При открытии/рендере главного экрана `.heat-scroll.scrollLeft` выставляется
  в максимум (`scrollWidth`), чтобы сегодняшний день был виден без прокрутки
  пользователем.
- Ячейка `.heat-day`: переиспользует принцип `.dot` — квадрат/скруглённый
  квадрат меньшего размера, чем в месяце. Состояния через `dayState`:
  - `plain`/`today` (не отмечено, не сегодня) — приглушённый акцентный тон
    (низкая opacity/фон-микс на `--habit-accent`).
  - `today` без отметки — тонкое кольцо `--today` поверх приглушённой заливки.
  - `marked`/`marked-today` — полная заливка `--habit-accent`.
  - Ведущие ячейки до первого дня 365-дневного окна (для выравнивания недели) —
    пустые (`pad`, как `.day.pad` сейчас).
- Клик по любой ячейке полосы (кроме круглой кнопки) → `data-action="open-habit"`
  (как сейчас на всей карточке) — полоса кликабельна только для перехода на
  экран месяца, не для точечной отметки прошлых дней с главного экрана.

## 3. Данные/логика — новый модуль `js/heat.js`

Чистый модуль, без DOM, зависит только от `js/stats.js` (`addDays`, `parseDate`,
`formatDate`) и `js/calendar.js` (`dayState`, `mondayOf` при необходимости).

- `heatWeeks(todayStr)` → `Array<Array<string|null>>`:
  - Внешний массив — недели (колонки), каждая неделя — массив из 7 элементов
    (строки, Пн=0 … Вс=6): `"YYYY-MM-DD"` или `null`.
  - Считает окно `[today - 364 ... today]` (365 дней включительно).
  - Ведущие `null` в первой неделе — если `today - 364` не понедельник,
    довыравнивает до начала той недели, но даты раньше `today - 364` **не
    выводятся** (остаются `null`) — то есть ровно 365 не-`null` дат на выходе,
    без урезания или расширения окна.
  - Последняя неделя оканчивается на `today` (текущий день недели — последняя
    непустая строка последней колонки; дни после сегодня в той же неделе не
    существуют, т.к. `today` — последний элемент окна).

### 3.1 Тесты `tests/heat.test.js` (`node --test`)
- Количество не-`null` элементов по всей структуре ровно 365.
- Последний не-`null` элемент последней недели равен `todayStr`.
- Первая неделя дополнена `null` слева ровно на `(weekdayIndex(today-364) )`
  ячеек (проверить на конкретной дате, где смещение ≠ 0).
- Все недели длиной 7.
- Окно, захватывающее 29 февраля високосного года, включает эту дату без
  сдвига остальных дат.
- Значения дат идут строго по возрастанию день-в-день без пропусков внутри
  365-дневного диапазона.

## 4. Шит добавления/редактирования — поле «Дата начала»

- Новое поле `<label class="field"><span>Дата начала</span>
  <input id="habit-start" type="date" max="${todayStr()}" value="..."></label>`,
  располагается после поля «Название», перед «Эмодзи».
- Новая привычка (`sheet.mode === 'add'`): значение по умолчанию — сегодня.
- Редактирование (`sheet.mode === 'edit'`): значение — `habit.createdAt`.
- При `pick-accent` (сохранение живого ввода перед перерисовкой шита) — так же
  сохранять `sheet.start = startEl.value`, как уже делается для `name`/`emoji`.
- При `save-habit`: читать `#habit-start`, валидировать `/^\d{4}-\d{2}-\d{2}$/`
  и `<= todayStr()`; если невалидно/пусто/в будущем → `todayStr()`. Передавать
  как `createdAt` в патч `createHabit`/`updateHabit`.
- Поле чисто информационное: не влияет на `dayState`, полосу, экраны
  месяца/года — как и раньше, любой день `<= today` доступен для отметки.

### 4.1 `js/storage.js`
- `createHabit(state, { name, emoji, accent, createdAt })` — если `createdAt`
  передан и валиден, использовать его; иначе `todayStr()` (как сейчас).
- `updateHabit` уже принимает произвольный `patch` — `createdAt` проходит как
  есть, доп. изменений не требует (нормализация — на стороне вызова в `app.js`,
  по аналогии с уже существующей нормализацией `name`).

## 5. Что не меняется
- `js/calendar.js`, `js/accents.js`, `js/sw-register.js` — без изменений.
- Экраны месяца (`#/h/:id`) и года (`#/h/:id/year`), контекстное меню, шит
  (свайп-закрытие, грабер), настройки/тема — без изменений.
- Модель данных `localStorage` (`habitTracker.v1`) — без изменений формата,
  только `createdAt` теперь может задаваться пользователем на создании/
  редактировании (раньше — всегда `todayStr()`).

## 7. Ручной чек-лист приёмки
1. Главный экран: у каждой привычки — полоса на 365 дней, горизонтальный
   скролл, открыта на сегодняшнем дне справа, без горизонтального скролла у
   остального контента страницы.
2. Круглая кнопка на карточке отмечает/снимает отметку сегодняшнего дня;
   изменение видно сразу на кнопке и на последней ячейке полосы; клик по
   кнопке не открывает экран месяца.
3. Клик по полосе (не по кнопке) → экран месяца этой привычки, как раньше.
4. Полоса окрашена акцентным цветом привычки (разные привычки — разный цвет).
5. Переходы карточка → месяц → год, контекстное меню, шит, настройки — ведут
   себя как в v2, без регрессий.
6. Шит добавления: поле «Дата начала» по умолчанию — сегодня, дату можно
   выбрать вручную (в т.ч. в прошлом), сохраняется в привычке.
7. Шит редактирования: поле «Дата начала» показывает текущую `createdAt`
   привычки, изменение сохраняется.
8. Дата начала не ограничивает отметку прошлых дней — привычка отмечается на
   любую дату `<= сегодня`, независимо от даты начала.
9. Офлайн (домашний экран): после бампа `CACHE` до v3 старый кэш удаляется,
   приложение открывается и работает.
10. `node --test` зелёный, включая новые тесты `tests/heat.test.js`.
